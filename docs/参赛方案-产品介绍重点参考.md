## 0. 产品命名（PPT 封面可用）

> **Synapse —— 基于大模型与可解释算法的智能学习规划**

- 动作落在**规划**：区别于模糊的“平台/系统/引擎”，一句话点破它解决“怎么安排学习”这件事。
- 技术点两样：**大模型**（满足赛道“依托 AI 大模型”的硬性要求）+ **可解释算法**（我们的差异化：排期 / 复习 / 诊断都说得清理由）。
- 不叫“RAG / 计划生成器”：实际用的是 BM25 / 知识图谱本地检索，核心是 SM-2 复习 + 确定性排期 + 学情诊断的闭环，不是生成一份文本计划。

## 1. 政策法规（合规就是卖点）

### 1.1 政策红利
- 国家持续推进**教育数字化战略行动**，鼓励人工智能在教育场景落地。
- 教育行业对学生数据安全与未成年人个人信息保护要求趋严（参考《中华人民共和国数据安全法》《中华人民共和国个人信息保护法》）。
- 学校 / 机构普遍存在“学生学习数据不能出校 / 不出班”的合规诉求。

### 1.2 我们的合规解法（差异化）
- SynapseV2 采用**无服务器、离线优先**架构：画像、学习计划、复习记录、知识图谱**全部存储在用户本机**。
- 大模型由用户自备 Key 或机构统一直连，**不经过中间服务器**。
- 结果：既满足个性化学习，又**天然降低数据集中存储与数据出境风险**，契合“数据不出校”的监管与经营诉求。

## 2. 行业痛点（每条都要“真痛”，不能泛泛）

1. **计划千篇一律**：市面多数“AI 学习”只是聊天外壳，计划不基于个人薄弱点、科目与可用时间生成。
2. **学完就忘、无法坚持**：缺少科学复习机制，不知道“何时该复习、复习什么”，学习效果难以沉淀。
3. **学情黑箱、机构家长不放心**：AI 为何这么排、孩子到底学没学会，说不清，无法建立信任。
4. **隐私与合规顾虑**：在线学习常把学生数据上传云端，家长、机构不放心。
5. **多平台割裂、开发成本高**：Web / 小程序 / 桌面各自维护一套，体验不一致、成本高。

### 痛点 → 我们采用的技术 → 为什么是它（建议做成一条主表贯穿全文）
| 行业痛点 | 我们用的技术 | 为什么用这个技术（能给 PPT 讲逻辑） |
| --- | --- | --- |
| 计划不是个性化 | 确定性排期算法（多科目合并、课表避让、逾期预警） | 计划要“准”和“可落地”，就不能靠模型临场发挥；算法写出确定逻辑，结果稳定、可解释、可审计 |
| 学了就忘 | SM-2 间隔重复算法（纯函数、零依赖） | 复习时机是数学规律，教科书级成熟算法，离线可算、跨端一致，是最省力又最可靠的解法 |
| 学情说不清 | 知识图谱 + 掌握度四档诊断 | “孩子到底学没学会”需要可查的证据链，而不是一句模糊评价；用真实复习数据聚合出红黄绿灰，点开可见理由 |
| 数据隐私顾虑 | 无服务器 + 本地 KV 存储 | 学生数据敏感，“不出本机”才同时满足合规和家长/机构信任；省掉云端也把云成本降到零 |
| 多端成本高 | 单一 TypeScript 核心 + 各端薄壳适配器 | 教育天然多端（电脑/手机/学校屏），只写一份逻辑多处复用，最符合“低成本落地到实际场景”的商用目标 |

## 3. 产品介绍

### 3.1 它是做什么的
用户告诉它学习目标（例：“两周复习高数，每天 90 分钟”），它自动生成**可按日执行**的学习计划，并提供完整闭环：**计划打卡 → SM-2 间隔复习 → 课程表避让 → 作业排期与逾期预警 → 知识图谱掌握度诊断 → AI 学情周报**。

### 3.2 已交付能力清单（PPT 可用）
- 多轮 AI 对话与意图编排（闲聊 / 澄清 / 制定计划 / 微调计划 / 答疑 / 记忆信息）
- 自由计划、积木计划、长期—短期—今日**三层计划**
- 课程表导入与**避让上课时段**
- 资料库导入（`.txt/.md/.pdf`）、**BM25 本地检索**、资料自动构图
- **SM-2 间隔复习**闭环
- **作业式计划**：老师布置 → 排进日程 → 打卡 → 逾期风险预警
- **知识图谱掌握度热力**（红/黄/绿/灰四档，可解释诊断）
- **AI 学情周报**（数字离线算、模型只写叙述）
- **多端已交付**：Web 与微信小程序跑同一套核心

### 3.3 数据主权与隐私（卖点）
数据只在用户本机，可一键导出为 JSON；不依赖云端存储。

### 3.4 技术成熟度佐证（PPT 数据卡片）
- 核心单元 / 黄金样本 / 边界 / 压力测试：**128/128 通过**
- Web 端到端（Playwright E2E）：**27/27 通过**
- core 对外导出：**201 个**模块；Web / 小程序 / core 类型检查通过；Web / 小程序生产构建通过

## 4. 核心技术（本次主题的核心，占篇幅最大）

> 本节约稿逻辑：**每个技术都按“目标 → 采用的技术 → 为什么选它”讲**，让评委看到“我们的做法是有依据的、不是炫技”。

### 4.0 总纲：我们要解决的本质问题
- 学习产品真正的难点，不是“生成一份计划”，而是**让计划执行得了、学完不忘、结果说得清、能在真实环境落地**。
- 我们的解法：**分工**——大模型负责“会说话、能叙事”（理解与表达），确定性算法负责“算得准、靠得住”（排期、复习、诊断），本地存储负责“记得住”（个人数据沉淀）。
- **金句：**
  > 接入大模型，是为了“会说话、能叙事”；保留规则算法，是为了“算得准、靠得住”。

### 4.1 问题：学生说话很随意，规则解析不了 → 采用大模型理解意图 → 为什么
- **问题**：学生不会按表单说话（“我数学函数总错，两周后考，一天挤一小时”），纯规则解析不出发起目标。
- **采用**：接入大模型做**意图理解与信息提取**（目标 / 科目 / 薄弱点 / 时间 / 截止日），以及开放性答疑、苏格拉底提示与学情周报的**自然叙述**。
- **为什么是它**：这些是生成式能力，规则算法写不出这种自然语言，也不该用正则去凑“人话”。所以这里交给大模型最合适——**它不是噱头，是唯一能理解自由表达的手段**。

### 4.2 问题：模型记不住、排不准、说不清 → 采用确定性算法 → 为什么
| 要解决的问题 | 采用的技术 | 为什么用这个技术 |
| --- | --- | --- |
| 记不住学过什么、何时该复习 | SM-2 间隔重复（纯函数，见 `packages/core/src/domain/review.ts`） | 复习时机是数学规律，用成熟算法离线可算、结果稳定，不依赖模型的临时记忆 |
| 排出受时长/课表/截止限制的日计划 | 多科目合并、课程表避让、逾期风险预警 | 排期要精确到“能不能完成”，必须确定性地做约束计算，不能靠模型“估” |
| 解释“为什么这么排”“学没学会” | 知识图谱掌握度四档诊断 | 需要可查的证据链，用真实 SM-2 字段聚合出红黄绿灰，点开可见理由 |
| 保证计划稳定、可审计 | 计划算法写死、行为跨版本一致 | 教学场景要求结果可复现、可回溯，不能随模型发挥而漂移 |
| 数据连续、越用越懂你 | 本地画像 / 资料 / 图谱 / 进度沉淀 | 只有把历史存在本机，才能跨会话持续累积，让产品“用越久越懂你” |

**形象比喻（PPT 可用）：**
> 大模型是“老师”，本地算法是“教务系统”。老师能讲解答疑，但“本周该复习什么、今天排什么、孩子哪里没学会、要不要预警”这种台账，靠教务系统算，不靠老师临场发挥。教育产品要落地，两者缺一不可——只有老师会飘，只有教务系统会僵硬；合起来才是能卖的产品。

### 4.3 整体架构：问题 → 采用的技术 → 为什么
| 目标 | 采用的技术 | 为什么是它 |
| --- | --- | --- |
| 一个核心、多端复用 | `protocol → domain → application → providers / storage / ports` 分层，纯 TS 零运行时依赖 | 教育场景天然多端（学生手机 / 家长电脑 / 学校屏幕），只写一套逻辑，各端只写薄壳——最低成本覆盖最多场景 |
| 无服务器、零云成本 | 本地 KV 存储 + 模型用户自备直连 | 一是规避数据出校的合规风险，二是省掉服务器运维，边际成本趋近于零，最利于商用落地 |
| 离线也能工作 | 检索用 BM25、排期/复习用纯函数算法 | 即使断网、模型不可达，计划与复习依然可用——把“靠谱”写进产品底层 |

**核心技术亮点汇总（可单独成页）：**
- **亮点一：无服务器 · 一个核心多端复用**——核心一字不改跑 Web / 小程序 / 桌面 / 安卓；商业化价值 = 零云成本 + 数据主权在用户 + 扩展新平台只需替换端口。
- **亮点二：可信学习算法 · 可解释诊断**——SM-2 复习 + 确定性排期 + 掌握度四档，模型一个数字都不许碰，结果可解释、可审计。

### 4.4 “凭什么比直接问大模型强”（正面对比）
| 维度 | 直接问大模型（DeepSeek / Kimi） | SynapseV2（算法 + 模型 + 本地记忆分工） |
| --- | --- | --- |
| 计划 | 一次性文本 | 可按日执行、可打卡 / 顺延的状态对象 |
| 记忆 / 复习 | 每次重新生成，不记得学过什么 | SM-2 间隔复习，自动安排下次复习 |
| 计划理由 | 说不清、不可靠 | 确定性规则 + 可解释诊断 |
| 个人数据 | 上下文一次性、跨会话不延续 | 画像 / 资料 / 图谱 / 进度沉淀在本机，越用越懂你 |
| 数据主权 | 上传云端 | 无服务器、全在本地、可一键导出 |

**一句话总结：**
> 大模型给你的是一张“计划纸”，我们给你的是一条“学习流水线”。同一个大模型在系统里只是排期时可选的一个零件，计划能否落地靠的是算法与闭环，不靠模型发挥。

## 5. 创意点（差异化灵魂）

**一句话创意：**
> 把“AI 大模型”从生成计划的聊天工具，变成离线可诊断的学习引擎。同一个模型，我们用来跑通“执行、复习、诊断、沉淀”的完整闭环，而不是让它替学生写一张计划。

**创意三点：**
1. **反直觉的离线优先**：同行都在“上云”，我们偏“无服务器、数据不出本机”。在教育“数据不能出校 / 未成年隐私”场景下，这是差异化护城河，也正踩合规痛点。
2. **模型只当“零件”不当“大脑”**：排期、复习、诊断由确定性算法完成，大模型只负责对话与叙述——行为可解释、可审计、不靠发挥，解决“AI 教学黑箱”的信任难题。
3. **一个核心、多端复用**：教育场景天然多端使用（家长电脑 / 学生手机 / 学校屏幕），一套引擎四端复用，直接对应落地广度。

## 6. 商业价值（重点）

### 6.1 成本优势（最直接的卖点）
- **零云服务成本**：无服务器、无云存储，模型由用户自备 Key 或机构统一直连，对比需要机房 / 云托管的教育 SaaS，**边际成本趋近于零**。
- **低部署 / 维护成本**：一套核心覆盖四端，降低多端开发与运营成本。

### 6.2 客户画像与付费（按近/远）
| 客户层 | 谁付钱 | 卖点 |
| --- | --- | --- |
| C 端 · 学生 / 家长 | 个人订阅 | 个性化计划 + 科学复习 + 隐私安全 |
| B 端 · 教培 / 学校 | 机构采购（本地部署） | “数据不出校”合规 + 可解释学情报告，增强信任与续费 |
| B 端 · 知识服务 / 自习机构 | 白标 / 一体化方案 | 一套核心嵌入自产品，低改造成本 |

### 6.3 可量化价值主张（PPT 要点）
- **提效**：从盲目刷题 / 无计划，到按掌握度精准复习，缩短无效学习时间。
- **留存**：SM-2 复习 + 打卡闭环带来**每日回访**，用户粘性远高于一次性答疑工具。
- **信任变现**：可解释的学情诊断报告，是家长愿付费、机构愿采购的“决策证据”。

### 6.4 延伸变现路径（远期）
- 学生端 → 沉淀出的学情数据（本地、脱敏后授权分析）→ 个性化教辅 / 题库推荐。
- 机构端 → **本地化部署 + 白标方案**，卖给缺自研能力的教培机构。
- 领域复制 → 同一套“目标—计划—执行—复习—诊断”引擎可平移到**考证、技能培训、职场学习**等场景。
